# 02 · 技术方案

> 版本：v1.0（2026-11-21）· 实测核验结果在 S1 回填

## 1. 架构总览

```
┌──────────────────────────── nex.exe（Python + PySide6）────────────────────────────┐
│  UI 层（qfluentwidgets）：主窗口 / 任务表格 / 添加任务 / 设置 / 日志面板              │
│  应用层：任务队列（SQLite 持久化）→ 单工作线程（QThread）→ 处理管线                 │
│  引擎层（子进程封装）：ffmpeg / ffprobe / realesrgan-ncnn-vulkan / rife-ncnn-vulkan │
└─────────────────────────────────────────────────────────────────────────────────────┘
                                   │ Vulkan / NVENC
                              NVIDIA GPU
```

- 处理引擎为**外部 exe 子进程**，不与主程序同进程，引擎崩溃不影响软件本体，也便于商用授权合规。
- 所有路径传参用参数列表（不经过 shell），全程 UTF-8，支持中文 / 空格路径。

## 4. 处理管线（单任务）

工作目录：`%TEMP%/NEX/<task_id>/`，任务结束（含失败 / 取消）清理。

1. **探测**：ffprobe 读取时长 / 帧率 / 分辨率 / 音轨；校验参数（模型与倍数匹配、输出不为空等）。
2. **抽帧**（0-5%）：`ffmpeg -i 输入 -fps_mode passthrough frames/%08d.png`
   - 实测注意：新版 FFmpeg 已移除 `-vsync`，必须用 `-fps_mode passthrough`。
3. **超分**（可选，5-45%）：`realesrgan-ncnn-vulkan -i frames -o frames_sr -n <模型> -s <倍数> -f png -g <GPU>`
   - **必须在引擎目录下运行**（模型由 `models/` 相对当前目录解析）。
   - 模型：`realesr-animevideov3`（动漫视频，支持 x2/x3/x4）/ `realesrgan-x4plus`（写实通用，仅 x4）/ `realesrgan-x4plus-anime`（动漫插画，仅 x4）。
   - 指定分辨率时：超分倍数取 `min(4, ceil(目标高度/原高度))`，合成阶段再精确缩放到目标尺寸。
4. **补帧**（可选，45-85%）：`rife-ncnn-vulkan -i frames_sr -o frames_fi -m <模型目录> -g <GPU>`
   - **必须在引擎目录下运行**，模型参数写相对目录名（如 `rife-v4.6`）。
   - 可用模型：rife / rife-HD / rife-UHD / rife-anime / rife-v2 / v2.3 / v2.4 / v3.0 / v3.1 / v4 / v4.6。
   - **版本说明**：官方 ncnn 包（20221029）内为 `rife-v4.6`（上游 RIFE 4.6），不存在 4.25/4.26；用户提供的 `Practical-RIFE/train_log` 为 **4.25（PyTorch）**，已作为可选引擎接入（见 4.3）。
   - 每遍默认输出 2 倍帧数（`-n` 可指定目标帧数）；目标 4x 跑两遍。
   - 指定帧率时选最小 2^n 使 `原帧率 × 2^n ≥ 目标帧率`，合成阶段精确降到目标帧率。
5. **合成**（85-100%）：
   ```
   ffmpeg -framerate <当前帧率> -i frames_final/%08d.png -i <原始视频>
     -map 0:v -map 1:a? -vf "fps=<目标帧率>,scale=<目标宽>:<目标高>:flags=lanczos"
     -c:v libx264 -crf 18 -preset medium -c:a copy -movflags +faststart <输出.mp4>
   ```
   - 编码器：默认 `auto` → **x264**（NVENC 需驱动 ≥610.00，当前 582.05 不可用，用户决定暂用 x264）；可手动 `--encoder nvenc`，失败时自动回退 x264。
   - 音频：`aac/mp3/ac3/eac3/alac` 直接 `-c:a copy`；其他编码转 `-c:a aac -b:a 192k`；无音轨时 `-an`。
   - 输出命名：默认 `<源文件名>_NEX.mp4`；重名自动追加 `_1`、`_2`。
   - 成片帧数以 ffprobe 读取的容器帧数为准。
6. **收尾**：输出移动到目标位置、清理临时目录、写数据库。

### 4.1 命令行实现（S3 已实现）

```bash
# 只超分（2x）
python -m nex.cli 输入.mp4 --sr realesr-animevideov3 --sr-scale 2
# 只补帧（2x）
python -m nex.cli 输入.mp4 --fi rife-v4.6 --fi-mult 2
# 超分 + 补帧（目标 1080p / 60fps）
python -m nex.cli 输入.mp4 --sr realesr-animevideov3 --sr-height 1080 \
  --fi rife-v4.6 --fi-fps 60 --output-dir 输出目录
```

- **任意帧率**：选择最小 2^n 遍插值（最多 3 遍 / 8x），合成阶段用 `fps=` 精确降到目标；例如 24→60 走 2 遍（96fps）再降到 60。
- **任意分辨率**：AI 超分倍数取 `ceil(目标高度/原高度)`（最大 4），合成阶段用 lanczos 精确缩放到目标宽高（保持比例，宽高取偶数）。
- **进度权重**：抽帧 5%；超分 / 补帧各 40%（只开一个时 60%）；合成取剩余。阶段内按已处理帧数或 ffmpeg `-progress` 输出计算。
- **临时目录**：`%TEMP%/NEX/<task_id>/`，成功 / 失败 / 取消都会清理（`--keep-temp` 可保留以便排查）。
- **取消**：Ctrl+C 或取消事件 → `taskkill /T /F` 杀掉进程树 → 清理临时目录 → 退出码 130。
- **失败**：中文原因 + 完整日志路径（`%APPDATA%/NEX/logs/<task_id>.log`）。
- **日志分离**：任务日志只记录结构化信息；引擎原始输出写入同目录 `<task_id>.engine.log`，便于排查且不干扰界面日志面板。

**进度**：按阶段加权；阶段内按"已处理帧数 / 总帧数"或 ffmpeg `-progress` 文件计算。
**取消**：置取消标志 → `taskkill /T /F` 杀掉进程树 → 清理临时目录 → 状态"已取消"。
**失败**：捕获非零退出码与 stderr 尾部写入日志，状态"失败"，用户可重试。

### 4.2 多语言（S5）

- `nex/i18n.py` 提供 `t()`：中文原文作为键，英文查 `EN` 字典，缺译回退中文。
- 语言保存在 `AppConfig.language`（`zh` / `en`）；启动时 `set_language()`。
- 界面、任务状态、日志阶段名、流水线日志与引擎错误均通过 `t()` 输出；任务日志在英文模式下为英文。
- 设置内切换语言后提示重启，确认后通过 `QProcess.startDetached` 以新语言重启。

### 4.3 Practical-RIFE 4.25（可选 PyTorch 引擎）

- **来源**：`Practical-RIFE/`（MIT）；`train_log/RIFE_HDv3.py` 中 `self.version = 4.25`，权重 `train_log/flownet.pkl`（24MB）。README 明确说明模型权重与代码同为 MIT，允许商用。
- **运行环境**：独立 `.venv-rife`（Python 3.11 + torch 2.11.0+cu128 + numpy + opencv-python），不污染主 `.venv`。
  ```
  py -3.11 -m venv .venv-rife
  .venv-rife\Scripts\python.exe -m pip install wheels\torch-2.11.0+cu128-cp311-cp311-win_amd64.whl
  .venv-rife\Scripts\python.exe -m pip install numpy opencv-python
  ```
- **推理封装**：`tools/practical_rife_runner.py` 只加载 IFNet 架构 + 4.25 权重，按帧目录输出 `%08d.png`；FP16；输出帧数 = 输入帧数 × 倍数（末尾复制补齐）。
- **接入方式**：模型选项「RIFE 4.25（PyTorch，需额外环境）」；环境缺失时界面自动隐藏该选项，CLI 会给出明确错误。默认补帧引擎仍为 ncnn 4.6。
- **性能实测**：24 帧 640×360 → 48 帧耗时 5.8 秒；24 帧 1280×720 → 48 帧耗时 7.7 秒；1 秒 360p 全管线约 10 秒。明显慢于 ncnn 4.6，但 4.25 更新、上游推荐用于多数场景/动漫。
- **打包影响**：`.venv-rife` 约 4.5GB；v1 默认不随安装包分发，S6 再决定是否作为可选高级引擎打包。
- **建议**：1080p 及以下使用 4.25；4K 显存/耗时较高，优先使用 ncnn 4.6 或降低分辨率。

## 5. 任务与状态

- 状态机：`等待中 → 处理中 → 已完成 / 失败 / 已取消`；失败与取消可重试（回到等待中）；删除仅删记录，不动视频文件。
- 单工作线程顺序处理（GPU 独占，避免争抢显存）。
- 启动时把遗留的"处理中"任务恢复为"等待中"。
- **S4 实现**：SQLite（`%APPDATA%/NEX/nex.db`，WAL 模式）保存任务参数与状态；`PipelineWorker`（QThread）顺序消费队列并通过信号回传进度 / 日志 / 完成状态；界面表格与日志面板均读取真实任务数据；异常退出遗留的临时目录在启动时清理（仅清理 24 小时前的）。

## 9. GPU 使用安全说明

1. 两个 AI 引擎使用标准 Vulkan 计算接口，**不超频、不修改电压/功耗上限、不刷新显卡固件**，只在驱动允许的正常范围内使用 GPU。
2. 处理时 GPU 占用接近 100% 属于正常负载，与大型游戏、视频渲染相当；显卡设计上可承受长时间满载。
3. 温度/功耗保护由显卡固件负责：接近上限会自动降频，极端情况会保护性关机，而不是损坏硬件。
4. 笔记本注意：保证出风口不被遮挡、机身垫高通风、环境温度正常；不建议在被褥/软垫上长时间满负载运行。
5. 8GB 显存下，4K 超分 + UHD 补帧可能显存不足；软件会捕获错误并提示切换模型/降低倍数（S3 实现显存与磁盘预检）。
6. 若显卡本身散热故障（风扇停转、硅脂干涸），任何高负载软件都有风险；建议定期清灰保养。
7. **实测数据**（3 秒样本，超分 + 补帧）：3D 占用最高 96%，温度最高 **57°C**，功耗最高 **65.8W**（当前功耗上限 66.4W，默认 50W，最大 115W），SM 频率约 2.5GHz；该卡目标温度（降频点）为 87°C。负载温度远低于降频点，90%+ 占用属于正常计算负载。
8. **软件温度保护**：处理中每 5 秒采样 GPU 温度并写入任务日志；达到保护上限（默认 88°C，CLI `--temp-limit` 可调，0 为关闭）时自动安全停止任务、清理临时文件并提示"显卡温度过高，请检查散热"。该保护是固件保护之外的额外兜底。
