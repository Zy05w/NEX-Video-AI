# 04 · 代码工程规范

> 版本：v1.0（2026-11-21）· 适用于全部 Python 代码

## 1. 环境与依赖

- Python 3.11（开发与打包统一版本）。
- 依赖安装：`pip install -r requirements.txt`；S2 起将实际使用版本锁定为精确版本号（`==`）。
- 不引入未评估的新依赖；确需引入先记入 devlog 并说明理由。

## 2. 目录与模块

- 按 `docs/02-技术方案.md` 第 3 节目录结构组织，一个文件一个职责。
- UI 文件只做界面与事件转发，业务逻辑放 `pipeline.py` / `worker.py` / `db.py`。
- 引擎调用全部集中在 `engines.py`，其他模块不直接拼命令行。

## 3. 命名

| 对象 | 规范 | 示例 |
|---|---|---|
| 模块 / 函数 / 变量 | snake_case | `build_sr_command` |
| 类 / 枚举 | PascalCase | `TaskStatus` |
| 常量 | UPPER_SNAKE | `MAX_SR_SCALE` |
| 界面文案 | 中文，集中在常量或模块内 | `"添加任务"` |

## 4. 类型与结构

- 公开函数写类型注解；任务参数、探测结果用 dataclass（`task.py`）。
- 状态用枚举，禁止裸字符串比较。

## 5. 错误处理

- 自定义异常：`NexError`（基类）、`EngineError`（引擎失败，携带阶段、命令行、stderr 尾部）。
- 用户可见提示：一句话中文原因 + 建议（如"请检查显卡驱动"）；技术细节写日志。
- 子进程：必须检查退出码；禁止 `shell=True`；参数一律用列表；全程 UTF-8。
- 取消：通过取消标志 + `taskkill /T /F` 进程树实现，捕获并忽略进程已退出的情况。

## 6. 日志规范

- 每任务一个文件：`%APPDATA%/NEX/logs/<task_id>.log`。
- 行格式：`HH:MM:SS [阶段] 消息`，阶段取值：`探测 / 抽帧 / 超分 / 补帧 / 合成 / 收尾`。
- 记录：阶段开始 / 结束、帧数、耗时、引擎 stderr 关键行、错误全文。
- 不记录用户隐私内容（路径按需显示）。

## 7. 配置与路径

- 禁止硬编码绝对路径；引擎路径统一由 `engines.py` 基于程序目录解析（开发态为项目根目录，打包态为 `sys._MEIPASS` / exe 同级）。
- 用户数据目录：`%APPDATA%/NEX/`，通过 `app_config.py` 获取。

## 8. 编码

- 源文件 UTF-8（无 BOM）；Windows 子进程读写显式指定 UTF-8。
- Windows 批处理（`.bat`）内容只用 ASCII、行尾 CRLF（中文交互放在 Python 中），避免 cmd.exe 解析乱码；换行规则见 `.gitattributes`。

## 9. Git 提交规范

- 提交信息：`<类型>: <中文描述>`，类型：`feat` / `fix` / `docs` / `test` / `refactor` / `chore` / `build`。
- 示例：`feat: 任务队列支持失败重试`。
- 一个提交只做一件事；阶段完成时提交一次。
- 不提交 `engines/`、构建产物、日志、数据库、密钥。

## 10. 验证要求

- 每个阶段完成前必须实际运行对应验证命令（见 `docs/05-开发执行步骤.md`），把输出摘要写入 devlog。
- 不允许"看起来对"就宣布完成。

## 11. 第三方组件兼容性

- qfluentwidgets 1.11.3 + PySide6 6.12：`SpinBox` 内部输入框会被布局压成 1px，导致数值不可见、无法输入。数字输入框统一使用 `nex/ui/widgets.py` 的 `make_spin_box()` 创建（内部设置最小宽度规避），不要在界面代码中直接实例化 `SpinBox`。
